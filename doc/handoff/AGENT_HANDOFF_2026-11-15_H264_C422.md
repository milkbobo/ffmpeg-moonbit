# H.264 §420 4:2:2 编码面收口

接续 §419。编码器色度面从 4:2:0 扩到 4:2:2（`chroma_format=2`，
`profile_idc` 122 High 4:2:2），CAVLC + CABAC 双熵、I/P/B 全调度、
流式=批式字节恒等，FFmpeg 逐帧 framemd5 全等零告警。

## 实现契约

- 入口 `h264_encode_frames` / `h264_encode_frames_cabac` /
  `H264StreamEncoder::open` 新增 `chroma_format~ : Int32 = 1`；
  只接受 1 与 2（0/3/负数拒收，有负例）。
- 几何：色度平面 `w/2 × h`（4:2:0 是 `w/2 × h/2`）；chroma hack
  `chroma_vshift = 0`；`cheight = pheight`。SPS 写
  `chroma_format_idc = 2`，profile 122。
- 深度面沿用 §412/§419 的 `qp_ext` / dequant / deblock / `chroma_qp`
  泛化；4:2:2 暂只开 8-bit（高位深 + 4:2:2 未接）。
- CLI：`--chroma {420|422}`（白名单、`raw_frame_size`、平面切分、
  `video_pixel_format` 的 `yuv422p` 命名全链打通）。CLI 端到端（docker
  native）6 帧 CAVLC/CABAC 产物与测试钉值**字节相同**，FFmpeg 解码
  逐帧 md5 全等（`yuv422p`，1713 B / 1308 B）。

## 本轮修掉的 5 个真 bug（全部为「4:2:0 下恰好等价」的硬编码）

1. **CABAC P 帧的 SPS 漏传 `chroma_format`**：
   `h264_enc_cabac.mbt` 批量循环里 `h264_enc_sps_rbsp_high(p, vbv~)`
   少了 `chroma_format~`。于是 SPS/PPS 说 4:2:0、编码按 4:2:2 →
   `pps.chroma_format` 回读成 1，整条 P 链按 4:2:0 走。
2. **借用解码器的镜像上下文硬编码 4:2:0**（`h264_cabac_mirror_new`）：
   `chroma_format: 1 / chroma_hshift: 1 / chroma_vshift: 1 /
   cheight: pheight/2`，且 refpic/cur 的 u/v 长度写死 `pheight/2`。
   这些字段喂 `h264_cabac_cbf_ctx`（nz/cbp 邻居）与 chroma 语法。
3. **CABAC 色度 AC 块数写死 4**：解码侧是 `4 * num_c8x8`
   （`num_c8x8 = chroma_format >> 1`），4:2:2 要写 8 块。三处写出
   （I 内联、P intra `h264_cabacw_chroma`、P inter、B 两处）。
4. **CABAC 着色度 DC 固定 4 系数**：4:2:2 的色度 DC 是 2×4 Hadamard
   （8 系数，`DECODE_SIGNIFICANCE(7, …)`，第 8 个隐含），四处写出。
5. **`coeff_abs_levelgt1_ctx` 未按 `is_dc422` 选行**：编码端只有
   `[0]`，解码端 4:2:2 色度 DC 用 `[1]`（escape 阶梯上下文）。

另修：CABAC/流式主循环所有 `pheight/2`（ref 缓冲、`next_u/next_v`、
`rec_u/rec_v`、`h264_enc_load_plane` 的 rows）；流式两处
`h264_b_refpic` 漏传 `chroma_h` → B 帧 `cheight` 错 → 流式与批式
从第一个 B 帧分叉。

## 排障方法（本轮 1 小时定位，可复用）

1. 先 FFmpeg 仲裁判「谁异类」：`ffmpeg -v warning -i x.264 -f framemd5 -`。
   `error while decoding MB 3 2` 说明编码端语法错，不是本仓解码器。
2. 帧数扫描（1..8 帧）定位最小复现：`n=1` ok、`n≥3` 挂在 frame=1 →
   说明 P 帧在 B 调度下才走到的分支。
3. 二分 fixture 内容（luma 渐变 / U 渐变 / V 行变 / 常量）隔离到
   「U 有残差」即崩 → 锁定色度语法。
4. **双侧同 idx 打印 `cbp`/`ccbp`**：编码 `write_cabac_mb_syntax`、
   解码 `h264_cabac_mb` 末尾各打一行，一比就看出编码 `nblk=4`、
   `ctx.chroma_format=1`——比逐 bin 追位快得多。
