# H.264 §419 12/14-bit 编码面收口

接续 §418。编码器深度面扩到 {8,9,10,12,14}，并收口一个 BDirect16 胜者
重建的潜伏 bug。两个 C 绑定技能（moonbit-c-binding /
make-moonbit-c-bindings）按惯例用于复用现有 FFmpeg 仲裁链
（docker ffmpeg-moonbit-ffref:nine-x264），无新增 C FFI。

## 实现契约

- `h264_enc_bit_depth_ok`：{8,9,10,12,14}——11/13 与 FFmpeg 的
  PATCHWELCOME 对齐拒收。
- `h264_enc_profile_idc`：>10 → 244（Hi444PP，bit_depth_luma_minus8 ≤ 6
  的唯一 profile，仍 4:2:0）；9/10 → 110；8 → caller base。
- 深度管线零新增：qp_ext（最大 87）/dequant（div≤14, qbits≤29, Int64
  中间量）/deblock（`qp + a - 6*shift` 表索引）/chroma_qp（51+depth_offset
  钳制）全部沿用 §412 泛化；fixture/打包 16-bit LE 泛化。
- CLI `--bit-depth {8,9,10,12,14}`；`video_pixel_format` →
  yuv420p12le/14le。

## 真 bug：BDirect16 胜者重建脏 cell（潜伏期）

`decide_b_mb` 胜者路径对 BDirect16 只 `h264_b_compensate`，不重跑
`h264_b_direct`。子分区候选（k=22 等）在 direct 试验**之后**运行，把
per-block cell 覆写成自己的运动；胜者若为 direct，补偿从脏 cell 读 MV——
部分象限按候选试验的 MV 预测（本地 recon≠解码，错值经 intra 邻居级联放大）。
解码器解析 k=0 时全象限重新推导，流始终合法（FFmpeg 零告警、本仓解码器
=FFmpeg 逐帧全等——编码器 recon 是唯一异类）。

触发形态：direct 胜出 + 其后 k=22 候选恰在分歧象限为纯 L1 子分区——
14-bit 决策标度才首次选中（同族三例：§416 skip 换指、§418 kind-22
preamble、本例 direct 胜者）。修复：BDirect16 胜者先
`h264_b_direct(全象限)` 再补偿。零钉值扰动（语法不变）。

## 排障方法沉淀（本例 4 小时定位）

1. FFmpeg framemd5 判别「谁异类」：本仓解码器（去块）=FFmpeg 逐帧全等
   → 流合法、编码 recon 错（排除解码侧）。
2. per-MB/per-block 差异网格 → 锁定单个 8x8 象限。
3. BQUAD（direct 推导）/BCMP（compensate 输入）双侧打印要**按图片段切分**
   （BFIN mb=0 边界；编码在前解码在后）——跨图片混读会得出「推导一致」的
   假阴性（本例第二屏才暴露 mv1=(4,-4) vs (-18,34)）。
