# H.264 4:4:4 I8x8

接续 C444_INTER8。4:4:4 IDR 在 `dct8x8=true` 时使用三平面 I8x8；
`dct8x8=false` 保留 I4x4。两种熵模式及 batch/stream 入口共用该路径。
本轮尚未启用 P 内帧内候选，也未启用 4:4:4 B 调度。

实现：

- 新 `h264_enc_i8444_pass`：luma 按 SAD 顺序选择四个预测模式，
  Cb/Cr 回放相同模式，各平面使用自己的 QP 和 intra dequant8 矩阵。
- 共用 `h264_enc_luma_i8_pass` 新增私有可选 matrix 参数，默认保持 0。
- I_NxN transform flag 写 1，模式只写四次，mirror 使用 2x2 复制模式网格。
- 三平面共享 CBP；CAVLC 逐平面写 interleaved 子列表并更新 nC；
  CABAC 走 cat 5/9/13，包含空平面的 coded_block_flag。
- i8_mbs 统计计入这些宏块。旧 MD5 锚点显式关闭 dct8x8，保留原 4x4 用例。

验证：

- 新 I8 专项及旧 c444 专项 8/8：两种熵模式，8/10 位输入，
  IDR 编码重建逐字节等于本地 skip_lf 解码，确认四个宏块均计入 i8_mbs。
- stream_c444 + c444_cabac 初步 6/6。
- native nine-x264 的现有 C 绑定 probe：CAVLC/CABAC × 普通/恒定 luma，
  四帧 I/P，各帧 FFmpeg 像素摘要与本地默认滤波解码一致，零解码诊断。
- moon fmt / moon check --target wasm --deny-warn / moon info --target wasm 通过。
- 无 C ABI 或所有权改动，本轮未运行 ASan。

后续：4:4:4 P 内 I8 候选、B 帧 MC/语法；可进一步比较三平面联合模式决策
与当前 luma SAD 决策的压缩效率。
