## 结果

把 §462–§466 累积的编码能力接到 CLI 上。此前 `encode-av1` 只能调
`--qp`/`--rd-lambda`/`--skip-pct`/`--skip-uniform`/`--me-range`，
§464 的参考年龄与 §465 的三维联合搜索在 CLI 上完全不可达。

新增选项：

| 选项 | 含义 |
|---|---|
| `--ref-age N` | §464：预测来自 N 帧前的重建（0 = 上一帧） |
| `--rd-ref-ages 0,1,2` | §465：对 q × skip × 参考年龄做联合搜索 |
| `--rd-skip-pcts 50,100` | §462/§465：联合搜索用的 skip 阈值列表 |

行为：

- 给了 `--rd-ref-ages` 就走三维联合搜索，**覆盖** `--ref-age` /
  `--skip-pct` / `--rd-lambda` 的独立路径（`--rd-lambda` 缺省按 1000）；
- `--rd-skip-pcts` 为空时沿用 `--skip-pct`；
- 校验：ages 必须 0..=7、pcts 必须 0..=100、`--ref-age` 非负；
- JSON 汇总新增 `ref_age` / `rd_ref_ages`（长度）/ `rd_skip_pcts`（长度）。

## 验证（端到端，含每帧逐像素自检）

CLI 每帧编码后用自家解码器逐像素自检，任何偏差直接 fail，所以「跑通」
本身即逐像素精确的证据。

- 4 帧平滑夹具：默认 16795 字节 / `--ref-age 2` 17247 字节 / 三维 22703
  字节 —— 三者不同，证明选项真的到达编码器。
- **λ 灵敏度**（4 帧噪声夹具，`--rd-ref-ages 0 --rd-skip-pcts 0`）：
  `--rd-lambda 0` → 10892 字节（省码，选大 q）；
  `--rd-lambda 1000000000` → 25201 字节（保真，选小 q）。
  两者相差 2.3 倍，证明三维路径的 λ 真的生效。
- 对照：直接 `--qp 40` 26717 字节 vs `--qp 220` 6673 字节，确认 q 本身
  影响显著。

## 排查记录（值得记）

中途我用「平滑渐变 + 每帧变化」的夹具测 λ，发现 λ=0/1e6/1e9 产出**完全
相同**的字节，一度怀疑 λ 在三维路径下没生效。写白盒探针直接测
`av1_enc_rd_select_q_skip_ref_int` 后确认库层正常（λ=0 选 q40+skip50、
λ=1e6 选 q40+skip0）。真正原因：那份夹具在 `--rd-skip-pcts 50,100` 下
skip 形态占优，把 q 维度差异掩盖了；换成 `--rd-skip-pcts 0` 并加大残差后
λ 立刻显现（10892 vs 25201）。

**教训：验证 RD 参数是否生效，必须让目标维度的代价差异压过其它维度，
否则会被误判为「参数没接上」。**

## 边界

- CLI 仍只支持 8-bit 4:2:0、64 倍数几何（与编码器能力集一致）。
- 三维搜索开销 = |q| × |skip| × |ref| × 单帧编码；ME 已由 §466 复用
  （每参考一次），但残差编码仍每组合全跑。
- 未接 `--rd-candidates`（q 候选固定用默认 `[40,100,160,220]`）。
